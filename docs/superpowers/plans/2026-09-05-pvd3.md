# PVD 3.0 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task in the current user-selected pvd-disaggregation checkout.

**Goal:** Implement Router-selected P/V/D with KV_READY admission and full-prompt retrieval every M Decode tokens.

**Architecture:** Reuse Entry/shard transport and add admission, consumer leases and batched retrieval. Retain a Decode session for the request lifetime; a scheduler adapter updates selected sequences before Decode using reusable staging and valid-token-only unpack.

**Tech Stack:** Python, PyTorch, aiohttp, Mooncake, Rust/reqwest.

**Spec:** ../specs/2026-09-05-pvd3-design.md

## Global Constraints

- No CAGRA/index implementation; selection is full_prompt.
- Keep D-generated KV local and preserve partial-page tails.
- Existing P TP1/2, V storage TP2, D TP2/4 limits remain.
- M defaults to 16 and excludes P's first token.
- Use current pvd-disaggregation branch; no push requested in this turn.
